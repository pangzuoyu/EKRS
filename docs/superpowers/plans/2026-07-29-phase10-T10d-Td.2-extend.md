## 设计要点

### Td.2.1 — chunk_id 路由

**唯一性争议**: Qdrant payload 中 `chunk_id` (T10a-5 写入) 是 string 字段;
`block_id` (UUID, 来自 ir_parser) 也存在 legacy chunk. Td.2.1 路由接受
**优先 chunk_id** (T10a-5 latest); 找不到时 fallback **doc_hash:block_id**
legacy path (T10a-5 命名空间共存规约).

**Auth**: `require_parser_token` (跟 /v1/constraints 一致). Read endpoint
总是需要 service-token — 不开放 public.

**Response 字段**: 仅暴露必要字段 (chunk_id, doc_hash, text, scope_path,
page_numbers, token_count, version, source_block_ids, numeric_hints
[*count only, not full payload*]). Nostrict/no-inference layer here —
这是 read-only proxy to Qdrant.

### Td.2.2 — ekrs_query

**直接 internal call (no HTTP round-trip)**: 调用
`ConstraintService.solve(query, context, scope, policy, overlay_hints, strict, top_k)`.
ConstraintService 是已存在的 internal class (在 `constraints.py` 路由 handler
内调用). Td.2 抽出 helper 让 MCP layer 复用.

**Decision**: 加 internal helper `evaluate_constraints(retriever, query, ...)` 
在 `rag/ekrs_rag/constraint_engine/__init__.py` 或 `rag/ekrs_rag/api/routes/constraints.py`
模块顶层. 这个 helper 接受 retriever + 参数, 返回 ConstraintResult 三闸门 pipeline.
HTTP route handler + MCP tool 都调它.

**R6 strict mode**: transparent pass-through. `strict=true` 时 solver 拒绝 inferred
hint (R6 iron rule). MCP wrapper 不应改写 strict 语义.

**Error isolation**: solver raise / 404 / 409 conflict 全部 catch, 转 MCP
content with `{"error": "..."}` 字段. 不用 HTTP status code (MCP wire 是
content-based).

### Td.2.3 — ekrs_get_block

**直接 Qdrant fetch**: `QdrantManager.get_payload_by_chunk_id(chunk_id)`,
不绕 HTTP. 跟 `ekrs_search` 一样 in-process 复用.

**Not-found**: Qdrant scroll 返回空 list → return `{"error": "chunk_id not found"}`
MCP content. parent §204: 永远不 crash server.

**Legacy fallback**: 如果 chunk_id 找不到, 尝试 doc_hash:block_id 解析
(切分 chunk_id on `:` 然后 search by block_id). 失败 → 返 "not found" 错误.
**Decision**: Td.2 不实现 legacy fallback — 仅 chunk_id. Legacy chunk 走
Td.1 already-shipped 的 `ekrs_search` + T10b-3 short-circuit. 后续 Td.3 评估
是否要 expose.

### Td.2.4 — DI 扩展

`build_server` 从 2 args 扩到 4: `build_server(retriever, qdrant, solver, dependencies)`.
保留 closure capture 模式 (Phase 5.5 E DI). 不引模块全局.

CLI entrypoint (`__main__` block) 传 None 给 retriever/qdrant/solver —
PoC 仅验证 wire-protocol. Production wiring (Td.3) 注入 real dependencies.

## Open questions (实施前关闭)

1. **`get_payload_by_chunk_id` 用 scroll vs direct GET?**
   Qdrant point ID 是 UUID (auto-generated), chunk_id 是 string payload field.
   GET requires point ID; scroll + filter 是正确路径. → **关闭**: scroll+filter,
   复用 `get_ingestion_status` pattern (lines 274-289).

2. **`evaluate_constraints` helper 放哪?**
   测试 import 路径要短. → **决策**: `rag/ekrs_rag/api/routes/constraints.py`
   顶层 (跟 handler 同模块, 不引新 file; MCP layer 通过 `from ...constraints import evaluate_constraints`).

3. **chunk_id 找不到时 silent fallback vs error?**
   Phase 6B+ 规范: not-found → 404. → **决策**: 返 `{"error": "chunk_id not found"}`
   MCP content. 不 fallback.

4. **BlockResponse Pydantic schema 字段?**
   Research doc §T9d-1 "返回 block 完整内容" 模糊. → **决策**: 暴露
   chunk_id + doc_hash + text (full, no 200-truncate) + scope_path +
   page_numbers + token_count + version + source_block_ids + numeric_hints
   (count only). 不暴露 vector (1024-d floats, 4KB). text 不砍 (这是
   document 精读, 不是 search preview).

5. **新 route membership in `apiv1` rate limit?**
   `./api/middleware/rate_limit.py` 是 `/v1/*` 全局 rate-limit. → **决策**:
   保持 (新 route 自动继承). 不另开窗口.
